# tg-companion

A Telegram chatbot whose every reply is generated by `claude -p` running as a
subprocess against your local Claude Code login. **No Anthropic API calls** —
inference goes through `claude login` (works with Pro / Max subscriptions, no
extra credentials needed).

Persona and behavior live in `CLAUDE.md` (auto-loaded by Claude Code from the
project's working directory). Conversation memory lives in `memory/` as plain
files; Claude reads them at the start of every turn and writes them back at the
end. There is no database.

This is a tiny, deliberately minimal codebase — about 200 lines of Python plus
a markdown persona file. It's meant to be forked, edited, and run on your own
laptop or a small VM.

## How it works

```
Telegram update
    └─> bot.py (python-telegram-bot, async)
            ├─ per-chat asyncio.Lock  (serializes turns within one chat)
            ├─ photos saved to memory/media/, prompt gains <image path="..."/>
            ├─ media-group albums debounced 1.5 s into one turn
            └─> subprocess: claude -p --allowedTools Read,Write,Edit,Glob,Grep,WebFetch,WebSearch
                    ├─ memory/{facts.md, summary.md, recent.jsonl} injected directly
                    │  into the prompt (so claude doesn't re-Read them every turn)
                    ├─ Reads any <image path="..."/> attachments
                    ├─ composes the reply (in its head)
                    ├─ optionally Writes a new long-term fact to memory/facts.md
                    └─ outputs the reply text on stdout
            └─> reply_text() → Telegram (with retry on transient timeouts)
            └─> orchestrator appends the turn to memory/recent.jsonl
                only after Telegram confirms delivery
            └─> orchestrator trims recent.jsonl past 200 lines → archive.jsonl,
                then summarizes the dropped turns into summary.md out-of-band
                (a separate detached claude -p, off the reply path), and
                garbage-collects media/ photos no longer referenced by recent.jsonl
```

The orchestration in `bot.py` is intentionally dumb. Most interesting choices —
what Cas (or your persona) reads, when she updates memory — live in `CLAUDE.md`
and are easy to tweak without touching Python. The one exception is compaction:
bounding `recent.jsonl` and growing `summary.md` is owned by `bot.py` and runs
out-of-band *after* the reply is sent, so it can never delay or deadlock a turn.

## Supported message types

| Incoming | Behavior |
|---|---|
| Text | Plain pass-through. |
| Photo (single) | Downloaded to `memory/<chat_id>/media/<msg_id>.jpg`; Claude reads it via the `Read` tool and replies. |
| Photo album (media group) | Debounced 1.5 s, then handled as a single turn with multiple `<image>` attachments. |
| Sticker | Routed as text `[贴纸] {emoji}` — the sticker's emoji is what reaches Claude. No image fetch. |
| Voice / video / audio / document | The orchestrator hands Claude an apology stub so the persona can decline in its own voice instead of a hardcoded fallback. |

## Quick start

```bash
# 1. Make sure `claude` is on PATH and logged in
claude --version
# if you're not logged in: `claude login`

# 2. Python venv + deps
python3 -m venv .venv          # may need: sudo apt install python3-venv
source .venv/bin/activate
pip install -r requirements.txt

# 3. Config
cp .env.example .env
cp CLAUDE.md.example CLAUDE.md
# edit .env:
#   TG_BOT_TOKEN=...           (from @BotFather)
#   ALLOWED_USER_IDS=12345678  (your TG user id, get it from @userinfobot)
#   CLAUDE_MODEL=...           (optional; e.g. claude-haiku-4-5-20251001 to save quota)
# edit CLAUDE.md:
#   fill in the persona TODO block at the top — name, style, what to call you, etc.

# 4. Run
python bot.py
```

`memory/` and `logs/` are created automatically on first launch. Open Telegram,
find your bot, send `/start`, then send a message.

## Files

| Path | What |
|---|---|
| `bot.py` | The orchestrator. Whitelist enforcement, per-chat asyncio lock, spawns `claude -p`, sends typing indicator while it runs, posts reply with retry on Telegram timeout. |
| `CLAUDE.md.example` | Template for the persona + behavior instructions. **Copy to `CLAUDE.md` and fill in.** Auto-loaded by `claude -p` from cwd. Your `CLAUDE.md` is gitignored. |
| `.env.example` | Template for runtime config. Copy to `.env`. |
| `memory/facts.md` | Long-term facts about the user. Updated by Claude when it learns durable info. (Created on first run.) |
| `memory/summary.md` | Rolling summary of older turns. Grown by an out-of-band `claude -p` whenever `recent.jsonl` is trimmed. |
| `memory/recent.jsonl` | Recent raw turns (user + assistant), JSON-per-line. Appended every reply. Trimmed by `bot.py` to the most recent ~100 lines once it passes 200. Photo turns carry an `image_path` field on the user row. |
| `memory/archive.jsonl` | Verbatim cold storage of turns trimmed out of `recent.jsonl`. The raw backstop if out-of-band summarization ever fails; never read on the hot path. |
| `memory/<chat_id>/media/` | Photos sent by the user, named `<msg_id>.jpg`. Garbage-collected after each turn: files no longer referenced by the chat's live `recent.jsonl` (rolled-out turns, album siblings) are deleted. |
| `logs/bot.log` | Rotating log (5 × 2 MB). |

## Configuration knobs (`.env`)

| Var | Default | Notes |
|---|---|---|
| `TG_BOT_TOKEN` | required | From @BotFather. Bot crashes at startup without it. |
| `ALLOWED_USER_IDS` | empty | Comma- or space-separated Telegram user IDs that may message the bot. Get yours from @userinfobot. **Empty means anyone can chat** — bot logs a loud warning, since random strangers will burn your Claude subscription quota. |
| `CLAUDE_MODEL` | unset | Passed through to `claude -p --model`. Leave blank to use your Claude Code default. Use a Haiku alias to save quota; use Opus/Sonnet for richer replies. |
| `CLAUDE_TIMEOUT_SECONDS` | 120 | Subprocess kill threshold. Sonnet/Opus on long memory files can take 60–90 s; haiku is much faster. |
| `CLAUDE_BIN` | `claude` | Absolute path to the `claude` binary if it isn't on PATH for the user that runs `bot.py`. |

## Running it as a service

For 24/7 operation on Linux, run under systemd as a user service. Example unit
(`~/.config/systemd/user/tg-companion.service`):

```ini
[Unit]
Description=tg-companion Telegram chatbot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/home/USER/tg-companion
# claude is usually under ~/.npm-global/bin which isn't on systemd's default PATH
Environment=PATH=/home/USER/.npm-global/bin:/usr/local/bin:/usr/bin:/bin
ExecStart=/home/USER/tg-companion/.venv/bin/python /home/USER/tg-companion/bot.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now tg-companion
sudo loginctl enable-linger $USER   # so it survives logout / SSH disconnect
journalctl --user -u tg-companion -f   # live logs
```

`CLAUDE.md` and files in `memory/` are re-read by `claude -p` on every
invocation, so editing them does **not** require a restart. Editing `bot.py` or
`.env` does.

## Networking

Telegram bots use **outbound** long-polling, not inbound webhooks. The host
running `bot.py` only needs internet access to `api.telegram.org` — no port
forwarding, no Tailscale, no public IP. Your Telegram client (phone, second
laptop, anywhere on the internet) can be on any network.

The only hard requirements on the host: it stays powered on, online, and
doesn't suspend. On a laptop, that usually means disabling lid-close suspend
or masking the systemd sleep targets.

## Two non-obvious gotchas

These bit during initial bring-up. They're fixed in the code; documented here
so you know what to look for if symptoms re-appear after a refactor.

**1. `claude -p --output-format text` only prints the LAST plain-text
assistant message.** If Claude's last action in a session is a tool call (e.g.
`Write` to memory), stdout is empty — even though Claude composed a perfectly
good reply. The fix is to order steps so the *very last* thing Claude does
each turn is emit the user-facing reply as plain text. `CLAUDE.md.example`
spells this out explicitly.

**2. python-telegram-bot's default 5 s timeouts are too tight.** On a slow
network or with a bigger model, `send_message` can hit `telegram.error.TimedOut`
and the reply (already saved in `memory/recent.jsonl`) never reaches Telegram.
`bot.py` bumps the timeouts to 15/30/30 s and wraps `reply_text` in a
4-attempt retry with exponential backoff. The reply is persisted before the
send, so retrying is safe — it never re-invokes Claude, only re-tries the
wire send.

## Heads-up: CLAUDE.md collisions

`claude -p` auto-loads `CLAUDE.md` from cwd **and** from `~/.claude/CLAUDE.md`
if one exists. If your global CLAUDE.md tells Claude things that conflict with
the persona (e.g. "you are Claude Code, the CLI assistant"), the persona may
feel off. Two options:

- Move conflicting content out of `~/.claude/CLAUDE.md`, or
- Switch `bot.py` to invoke `claude -p --bare --append-system-prompt-file CLAUDE.md ...`
  to skip auto-discovery entirely.
