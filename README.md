# tg-companion

A Telegram chatbot whose every reply is generated by `claude -p` running as a
subprocess. Persona and behavior are defined in `CLAUDE.md` (auto-loaded by
Claude Code). Conversation memory lives in `memory/`.

No Anthropic API calls — inference uses your local `claude login` (e.g. Max
subscription).

## Architecture

```
Telegram update
    └─> bot.py (python-telegram-bot, async)
            └─> per-chat asyncio.Lock  (serializes the same chat)
                    └─> subprocess: claude -p --allowedTools "Read,Write" ...
                            ├─ reads CLAUDE.md (persona + instructions)
                            ├─ reads memory/{facts,summary,recent}
                            ├─ composes reply -> stdout
                            └─ writes back memory/recent.jsonl (and summary.md when compacting)
            └─> stdout -> reply_text() -> Telegram
```

## Phase 1 install

```bash
# 1. Make sure `claude` is on PATH and already logged in:
claude --version
# (if not logged in: `claude login`)

# 2. On this Ubuntu box, python3-venv and python3-pip aren't installed yet.
#    One-time:
sudo apt install python3-venv python3-pip

# 3. Python deps
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 4. Config
cp .env.example .env
cp CLAUDE.md.example CLAUDE.md
# edit .env:
#   TG_BOT_TOKEN=...           (from @BotFather)
#   ALLOWED_USER_IDS=12345678  (your TG user id from @userinfobot)
#   CLAUDE_MODEL=...           (optional; e.g. claude-sonnet-4-6 to save quota)
# edit CLAUDE.md:
#   fill in the persona TODO block at the top — name, style, etc.

# 5. Run (memory/ and logs/ are auto-created on first launch)
python bot.py
```

Open Telegram, find your bot, send `/start`, then send any message.

## Files

| Path | What |
|---|---|
| `bot.py` | Telegram orchestrator. Whitelist, per-chat lock, spawns `claude -p`, sends typing indicator, posts reply, retries on Telegram timeout. |
| `CLAUDE.md.example` | Template for the persona + behavior instructions. **Copy to `CLAUDE.md` and fill in.** Auto-loaded by `claude` from cwd. Your `CLAUDE.md` is gitignored. |
| `memory/facts.md` | Long-term facts about the user. Updated by Claude when it learns durable info. |
| `memory/summary.md` | Rolling summary of older turns. Appended to when `recent.jsonl` exceeds 200 lines. |
| `memory/recent.jsonl` | Recent raw turns (user + assistant). Appended every reply. Compacted at 200 lines. |
| `logs/bot.log` | Rotating log (5 × 2MB). |

## Knobs in `.env`

| Var | Default | Notes |
|---|---|---|
| `TG_BOT_TOKEN` | (required) | from @BotFather |
| `ALLOWED_USER_IDS` | empty = open | Comma/space separated TG user IDs. Empty means anyone can chat — bot logs a loud warning. |
| `CLAUDE_MODEL` | (default) | Pass-through to `claude -p --model`. Leave blank to use your Claude Code default. |
| `CLAUDE_TIMEOUT_SECONDS` | 120 | Subprocess kill threshold. |
| `CLAUDE_BIN` | `claude` | Override if `claude` isn't on PATH for the user that runs `bot.py`. |

## Testing

Quick subprocess sanity check (without Telegram):

```bash
cd ~/tg-companion
echo '你好' | xargs -I{} claude -p --allowedTools "Read,Write" --permission-mode acceptEdits "用户说: {}"
```

If that prints a reply and `memory/recent.jsonl` gains lines, the Claude side is working.

## Heads-up: CLAUDE.md collisions

`claude -p` auto-loads CLAUDE.md from the cwd **and** from `~/.claude/CLAUDE.md`
if you have one. If your global CLAUDE.md gives Claude conflicting instructions
(e.g. "you are Claude Code, the CLI assistant") and the persona feels off,
options:

- Move conflicting global content out of `~/.claude/CLAUDE.md`, or
- Switch `bot.py` to invoke `claude -p --bare --append-system-prompt-file CLAUDE.md ...`
  to skip auto-discovery (deferred to Phase 2 if needed).
